# Мост Kaspi между действующим сайтом и новым

Короткая спецификация для того, кто правит бэкенд `sert.imbir.kz`.

## Зачем

Ссылка и QR Kaspi несут **только номер заказа** — суммы в них нет. Вид услуги
и сумму приложение Kaspi спрашивает у бэкенда мерчанта, и ходит оно на
`sert.imbir.kz`. Новый сайт заводит заказы у себя, старый про них не знает —
покупатель упирается в «проверьте правильность ввода данных».

Пока Kaspi не перенаправили на новый домен, старый сайт проксирует: не найдя
заказ у себя, спрашивает новый сайт, а после оплаты сообщает ему о ней.
**Протокол Kaspi целиком остаётся на стороне старого сайта** — новому нужны
только два простых вызова ниже.

## Авторизация

Оба вызова закрыты общим секретом. Он передаётся заголовком — любым из двух:

```
X-Bridge-Token: <секрет>
Authorization: Bearer <секрет>
```

Секрет выдаётся отдельно, в репозитории его нет. Без него — `401`.
Если секрет не прописан на новом сайте, оба адреса отвечают `503`.

## 1. Проверка заказа

Вызывается, когда Kaspi спрашивает про заказ, которого нет в базе старого сайта.

```
GET https://new.imbir.kz/api/kaspi/order/{номер заказа}
```

Заказ найден — `200`:

```json
{
  "found": true,
  "orderId": "cmt2o1r4h000027pehaof039a",
  "name": "Новый Электронный 20000",
  "amountKzt": 20000,
  "amountTiyn": 2000000,
  "status": "pending",
  "city": "Астана",
  "salon": "Имбирь на Мәңгілік Ел",
  "createdAt": "2026-08-21T09:14:22.000Z"
}
```

Заказа нет — тоже `200`, но `{"found": false}`. Это обычный ответ, а не сбой:
старый сайт по нему отвечает Kaspi «заказ не найден».

- `name` — вид услуги, его покупатель видит в приложении Kaspi.
- `amountKzt` — сумма **к оплате**, уже со скидкой промокода, если он был.
  `amountTiyn` — та же сумма в тиынах, если шлюзу удобнее так.
- `status`: `pending` — ждёт оплаты, `paid` — уже оплачен (принимать оплату
  второй раз не надо), `expired` — просрочен, но оплату примем.

## 2. Уведомление об оплате

Вызывается после того, как Kaspi подтвердил оплату.

```
POST https://new.imbir.kz/api/kaspi/order/{номер заказа}/paid
Content-Type: application/json

{ "amountKzt": 20000, "txnId": "номер транзакции Kaspi" }
```

Тело необязательное, оба поля можно не слать. Но если сумма передана и не
совпала с нашей — ответим `409 amount_mismatch`: заплатить меньше и получить
полный сертификат не должно получаться.

Ответ `200`:

```json
{ "ok": true, "status": "fulfilled" }
```

- `fulfilled` — заказ оплачен, сертификат выпущен и уходит на почту.
- `already_fulfilled` — уже обрабатывали раньше. **Повторный вызов безопасен**,
  второй сертификат не появится. При сомнениях лучше вызвать ещё раз.
- `409 not_payable` — заказ отменён или возвращён, оплату принимать нельзя.
- `404 order_not_found` — такого заказа у нас нет.

Просроченный заказ (`expired`) оплату принимает: покупатель мог заплатить
позже, чем через 30 минут, и терять его платёж нельзя.

## Как выглядит ссылка на оплату

Новый сайт собирает её так же, как действующий, — меняется только номер:

```
https://kaspi.kz/pay/PodarochniisertifikatImbir?service_id=11079&15991=cmt2o1r4h000027pehaof039a
```

Номер заказа — наш `order.id`, 25 символов, латиница и цифры. Поле в форме
Kaspi буквы принимает (проверено). Номер виден в админке нового сайта, так что
платёж всегда можно сверить вручную.

## Проверить, что мост жив

```bash
curl -H "X-Bridge-Token: СЕКРЕТ" https://new.imbir.kz/api/kaspi/order/тест
```

Ответ `{"found":false}` — мост работает. `401` — не тот секрет. `503` — секрет
не прописан на новом сайте.
