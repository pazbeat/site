## В работе

### Кошелёк (Apple Wallet + Google Wallet)

Задача: сертификат добавляется в кошелёк, при погашении баланс уменьшается,
использованный помечается как погашенный.

- [x] Схема `WalletPass` + `WalletDevice`, миграция `20260813120000_wallet_passes`
- [ ] Доменный слой: поля пропуска, баланс, признак `voided` (чистые функции + тесты)
- [ ] Генерация `.pkpass` за интерфейсом провайдера + мок без ключей
- [ ] Apple Wallet Web Service: 4 эндпоинта + push через APNs
- [ ] Google Wallet: ссылка добавления + PATCH объекта при погашении
- [ ] Связка с `lib/altegio/redemptions.ts` + кнопки в интерфейсе

**Важно про Apple:** карта обновляется только если в пропуске есть
`webServiceURL` и `authenticationToken`. У текущего сайта заказчика их нет —
там пропуск статический, баланс на нём замирает навсегда. Удалить карту из
кошелька программно нельзя: используем `voided`, карта сереет.

**Источник данных для баланса готов** — `lib/altegio/redemptions.ts` каждые
15 минут тянет остаток из CRM, в базе есть `balanceKzt` и статусы.

## Чем заблокировано

| Что | Чего ждём |
|---|---|
| Halyk ePay | ClientID, ClientSecret, TerminalID от банка (услуга подключается к существующему счёту, `Epay@halykbank.kz`) |
| Apple Wallet | Pass Type ID сертификат + приватный ключ, APNs Auth Key |
| Google Wallet | проект Google Cloud, сервисный аккаунт, доступ к Wallet API |
| Kaspi | на 2026-08-17 шлюз payqr.kz отвечал 504 и таймаутами — проверить, когда поднимется |

Тестовые реквизиты Halyk просить не нужно — они публичные:
https://epayment.kz/docs/Test-credentials

## Требования Halyk, влияющие на код

- `invoiceId` — только цифры, 6–15 знаков, уникальность по последним 6 цифрам.
  У нас заказы с UUID, понадобится отдельный числовой счётчик.
- `postLink` обязателен — это наш URL, куда банк шлёт результат оплаты.
  То есть вебхук есть, в отличие от Kaspi.
